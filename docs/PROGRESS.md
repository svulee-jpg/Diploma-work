# Журнал прогресса

## 22.11.2026 (ночь): дашборд управляющего
**Сделано**
- `/dashboard`: показатели за «сегодня / 7 / 30 дней» со сравнением с предыдущим периодом: выручка, заказы, средний чек, доля заказов с выпечкой, доля узнанных по лицу, принятые подсказки ИИ (и оценка допвыручки), время ожидания и приготовления, риск списаний, программа лояльности; графики по дням и по часам, популярные позиции, таблицы подсказок и списаний.
- Блок **«Что делать»**: правила превращают метрики в действия (риск списаний, пик нагрузки и смена, долгое ожидание, низкое принятие подсказок, мало допродаж, низкая узнаваемость). Это элемент именно СППР: система предлагает решения, а не только показывает цифры.
- `scan_log`: журнал результатов распознавания (без изображений и векторов).
- `simulate_day`: симулятор активности киоска для демо (**все данные синтетические**): `python -m smartpos.simulate_day --days 7 --per-day 45 [--offset 7 --seed 12]`.
- 15 автотестов проходят.

**Важно для диплома**
Принятие подсказок, время приготовления и узнаваемость в демо смоделированы, поэтому их нельзя приводить как результаты. Реальные значения появятся после пилота; формулы расчёта (`analytics.py`) уже готовы.

## 22.11.2026 (ночь): очередь заказов
**Сделано**
- Заказ из киоска (или с кассы) попадает в очередь со статусами `новый → готовится → готов → выдан` (недопустимые переходы отклоняются).
- `/queue`: экран бариста в виде трёх колонок; на карточке номер заказа, источник (киоск/касса), имя гостя, его предпочтения («Без сахара»), состав, время ожидания (подсветка после 4 и 8 минут), звуковой сигнал о новом заказе.
- `/board`: публичное табло выдачи («Готовятся» / «Готовы»), только номера, без персональных данных.
- Киоск после оплаты показывает номер заказа.
- В БД сохраняются метки времени `started_at`, `ready_at`, `done_at`: из них считается время приготовления и ожидания для дашборда управляющего (следующий шаг).
- Миграция БД для старых данных, 13 автотестов проходят.

## 22.11.2026 (поздно вечером): киоск самообслуживания для гостя
**Решено** (видение команды): главный интерфейс теперь экран гостя на планшете у стойки; экран бариста остаётся для персонала.
- `/` и `/kiosk`: киоск (камера узнаёт гостя → «Доброе утро, Сауле!» → подсказки напитков → меню → допродажа выпечки → оплата Kaspi QR/карта (демо) → бонусы).
- `/barista`: прежний экран персонала.

**Сделано**
- `backend/smartpos/context.py`: контекст (время суток, сезон, праздники РК за 7 дней, выходной), акции (утренний капучино −15%, летний happy hour −20%, скидка −25% на выпечку с истекающим сроком), сезонные напитки (Тыквенный латте осенью, Новогодний раф зимой), подсказка напитков = привычки гостя (с затуханием и по времени суток) + сезон/время + популярность по сети + акции/праздник.
- API: `/api/kiosk/menu`, `/api/kiosk/suggest`, чекаут с серверным пересчётом цен по акциям (`apply_promos`).
- Киоск: крупный сенсорный интерфейс в леопардовой палитре, демо-панель (подмена даты и времени, симуляция гостя), регистрация по лицу с экраном согласия, автосброс при бездействии.
- 11 автотестов проходят.
- Заметки о новизне и патенте: [IP_AND_NOVELTY.md](IP_AND_NOVELTY.md).

**Дальше**
- Очередь заказов на экране бариста (статусы «готовится / готов»).
- Дашборд управляющего (средний чек, принятие подсказок, списания): возвращает в проект «операционную оптимизацию сети».
- Реальные данные или пилот; замер FAR/FRR; liveness-проверка.

## 22.11.2026 (вечер): реальное распознавание лиц
**Сделано**
- Движок InsightFace (`buffalo_l`, ArcFace) подключён и проверен: модель хранится в `backend/data/insightface/` (не в git, ~280 МБ, скачивается при первом запуске).
- Проверка на тестовом снимке из пакета: найдено 6 лиц; один человек (оригинал и зеркальное отражение) даёт косинусное сходство ≥ 0,93, разные люди ≤ 0,21. Это лёгкие условия: для реальных (свет, ракурс, маска) порог нужно калибровать.
- Порог сопоставления теперь настраивается (`SMARTPOS_MATCH_THRESHOLD`, по умолчанию 0,45).
- В интерфейс бариста добавлен захват с веб-камеры (в режиме `insightface` вместо симуляции); кадр не сохраняется, на сервере остаётся только вектор.
- Интеграционный тест реального движка (`tests/test_insightface.py`): регистрация лица, повторное узнавание, отказ на кадре без лица. Всего 7 тестов проходят.

**Дальше**
- Замерить FAR/FRR на живых людях (добровольцы, с согласием): разные освещение, ракурс, очки/маска, 30–50 снимков.
- Защита от подмены (фото на экране телефона): liveness-проверка, пока не реализована.
