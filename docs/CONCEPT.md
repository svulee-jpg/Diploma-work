# Концепт: Smart POS & Loyalty

## Решение по охвату (22.11.2026)
Ядро диплома: **Smart POS** (распознавание гостя + рекомендации бариста). Тема из заявления
(«СППР на основе ИИ для оптимизации операционной деятельности сети кофеен») раскрывается так:
Smart POS это **СППР уровня кассы**: система помогает бариста принимать решение «что предложить этому гостю
прямо сейчас» и оптимизирует операционные показатели: скорость обслуживания, средний чек, списания.

**Как защищать связь с темой:**
- Объект: операционная деятельность точки (обслуживание в часы пик, допродажи, списания).
- Предмет: ИИ-система поддержки решений бариста на кассе.
- Операционные метрики: время обслуживания, средний чек, доля принятых подсказок, списания выпечки с истекающим сроком.
- Масштаб «сети»: единая облачная база лояльности и модель для нескольких точек (Espresso Day, Luna Coffee); один гость узнаётся в любой точке.

## Пользовательский сценарий
1. Камера у кассы получает кадр, детектор находит лицо, модель считает эмбеддинг (512 чисел).
2. FAISS ищет ближайший вектор в базе согласившихся клиентов (косинусное сходство, порог 0.60).
3. На экране бариста: имя, число визитов, бонусы, любимый заказ, предпочтения.
4. Рекомендательная модель оценивает вероятность добавить каждую позицию (выпечку) с учётом гостя, напитка, времени суток; истекающий срок годности даёт ранговый буст.
5. Бариста получает готовую реплику; оплата в один клик, бонусы (5% кэшбэк) начисляются и списываются автоматически.
6. Новый гость: сценарий «холодного старта» (регистрация за 5 секунд, 200 приветственных бонусов, только с согласием).

## Модель рекомендаций (как работает сейчас)
Логистическая регрессия, шесть признаков на пару (гость, позиция в данном заказе):
доля чеков гостя с позицией, недавняя доля (30 дней), доля в то же время суток,
P(позиция | напиток), P(позиция | время суток), число визитов.
Персональные признаки сглаживаются к общему среднему, поэтому для нового гостя модель
автоматически опирается на поведение похожих гостей (гибрид с коллаборативной частью).
Обучение по времени: первые 80% заказов train, последние 20% test, история клиента только из прошлого (без утечки).

## Первые метрики (синтетические данные!)
| Модель | AUC | hit@1 (заказы с допродажей) |
|---|---|---|
| Гибридная (наша) | 0.951 | 0.951 |
| Бейзлайн: самое популярное | 0.643 | 0.376 |
| Бейзлайн: популярное для напитка | 0.760 | 0.426 |

⚠️ Данные сгенерированы по явным правилам, которые модель легко восстанавливает. Эти цифры доказывают,
что пайплайн работает, но **не** являются оценкой реального эффекта. Для диплома нужно:
(1) получить обезличенные чеки у кофеен или (2) провести A/B-пилот и мерить конверсию подсказок (`/api/metrics` уже логирует).

## Правовые аспекты (РК)
Биометрические данные относятся к персональным данным, нужно согласие субъекта (opt-in), цель обработки,
возможность отзыва. Реализовано: согласие обязательно при регистрации, хранятся только векторы,
отзыв согласия удаляет вектор. Для текста диплома нужно сверить формулировки с Законом РК «О персональных данных и их защите».

## Ограничения и риски
- Реальная точность распознавания зависит от освещения, ракурса, масок; порог 0.60 нужно калибровать на реальных лицах (FAR/FRR).
- Защита от подмены (фото, видео) в MVP не реализована (liveness detection: развитие).
- Интеграция с iiko / Poster / r_keeper не делается, MVP работает рядом с кассой.
