# Протокол оценки распознавания лиц (FAR / FRR)

Ответственный: Алинур (роль A), глава 3.2. Скрипт: [backend/smartpos/eval_faces.py](../backend/smartpos/eval_faces.py).
Методика опирается на ISO/IEC 19795-1 (источник в [LITERATURE_REVIEW.md](../thesis/LITERATURE_REVIEW.md)); текст стандарта нужно прочитать перед цитированием.

## Зачем это нужно
Порог узнавания (`SMARTPOS_MATCH_THRESHOLD`, сейчас 0,45) пока выбран на одном тестовом снимке. Для диплома нужно показать, **как часто система ошибается** на реальных людях и при каких условиях:
- **FAR**: незнакомца приняли за клиента (приветствие чужим именем, нарушение приватности);
- **FRR**: своего клиента не узнали (потеря удобства);
- **FTA**: лицо на кадре не нашли;
- порог, выбранный по цели (например, FAR не больше 0,1%), вместо порога «на глаз».

## Кого снимать и сколько
- **Добровольцы**: минимум 15, лучше 25–30 (однокурсники, друзья, семья). Чем больше разных людей, тем уже доверительные интервалы.
- **Снимков**: 6–10 на человека. Цель FAR 0,1% можно проверить, только если пар «разных людей» не меньше 3000 (скрипт сам предупреждает). При 15 людях по 8 снимков пар около 6700, достаточно.
- Пары снимков одного человека зависимы, поэтому интервалы считаются бутстрэпом по людям, а не по парам.

## Что снимать (условия)
Одно условие = один префикс в имени файла. Минимальный набор на человека:

| Префикс | Условие | Снимков |
|---|---|---|
| `base` | анфас, хороший свет, без очков и маски; **этот снимок = регистрация в киоске** | 2 |
| `dim` | слабый свет (вечер, лампа сбоку) | 1–2 |
| `back` | контровой свет (окно за спиной) | 1 |
| `side` | поворот головы примерно на 30° | 1–2 |
| `glasses` | очки (если носит) или снять очки | 1 |
| `mask` | медицинская маска или шарф | 1 |
| `far` | на расстоянии около 1,5 м от камеры, как у стойки | 1 |

Снимать лучше **на камеру, которая будет в киоске** (планшет или веб-камера), а не на телефон, иначе ошибки будут оптимистичнее реальных.

## Съёмка через браузер (рекомендуется)
Страница `/collect` сама показывает условия, делает снимок с обратным отсчётом 3-2-1 (или пробел), складывает файлы по папкам и считает, сколько осталось. Она **выключена по умолчанию**, не работает в публичном демо и принимает запросы только с этого же компьютера.
```bash
cd backend
SMARTPOS_COLLECT=1 SMARTPOS_FACE_ENGINE=insightface ../.venv/bin/python -m uvicorn smartpos.main:app --port 8010
```
Откройте http://localhost:8010/collect, введите код участника (`s01`), отметьте, что согласие подписано, и следуйте списку условий. Если лицо на кадре не найдено, страница предупредит (снимок при этом сохраняется, чтобы FTA считался честно; можно удалить кнопкой «Удалить последний снимок»).
Проверка «лицо найдено» работает только с `SMARTPOS_FACE_ENGINE=insightface` (проверено: на фото с лицом `True`, на пустом кадре `False`).
Открывайте страницу в обычном Chrome или Safari и разрешите камеру (во встроенных окнах редакторов камера заблокирована). Если команда пишет «address already in use», порт 8010 занят старым сервером: остановите его (Ctrl+C в его терминале) или поменяйте `--port 8010` на другой, например `8013`, и адрес в браузере тоже.

## Как складывать файлы (если снимаете не через страницу)
Папка `backend/data/faces_eval/` (в git не попадает, это персональные данные):
```
backend/data/faces_eval/
  s01/base__1.jpg  base__2.jpg  dim__1.jpg  mask__1.jpg ...
  s02/base__1.jpg  ...
```
- Имя человека в папке только **кодом** (`s01`, `s02`), без фамилий. Таблицу «код ↔ имя» не храните вместе с фото (лучше вообще не вести).
- Без префикса `__` в имени файла условие считается `base`.

## Запуск
```bash
cd backend
../.venv/bin/python -m smartpos.eval_faces --data data/faces_eval
```
Результат в `backend/data/eval_report/`: `report.md` (таблицы), `report.json`, графики `score_distributions.png` и `far_frr_det.png`.
Проверка конвейера без добровольцев: `--demo` (результат помечен «не результат исследования»).

Параметры: `--threshold 0.45` (текущий порог), `--target-far 0.001` (цель для рекомендации порога).
